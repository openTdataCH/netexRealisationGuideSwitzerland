# Markdown Link Checker

This tool checks all relative links in markdown files and warns if the target files don't exist.

## Installation

### Build tools with uv

The recommended way is to [build the tools with uv](../README.md#how-to-setup-and-run-the-build).

#### Tools script

The tools build installs a wrapper script `check-links` to `.venv/bin`.

## Usage

In order to get a detailed usage message, run the tool with option `-h` or `--help`:
```bash
python check_links.py -h
```
Or, with installed script:
```bash
check-links -h
```
See [the tools README](../README.md#how-to-run-a-tool) about how to run a tool.

### Usage Example

```bash
python check_links.py --docs src
```

## Features

- Checks all markdown files (`*.md`, `*.MD`, `*.markdown`, `*.Markdown`) in the specified folder and subfolders
- Validates relative links (ignores absolute URLs and anchor links)
- Handles links relative to the main folder (`../` paths)
- Handles links relative to the current file
- Understands links that are already prepared for the generated web site and checks them against the sources they are generated from (see `tools/toolchain.py`):
  - `site/tables/<Name>.md` / `site/tables/<Name>.html` are generated by the md_builder from `<docs>/templates/<Name>.xml`
  - `site/xml-snippets/<Name>.xml` is generated by the xml_snippets tool from `<docs>/templates/<Name>.xml`
  - `<Page>.html` next to a markdown file is rendered by Jekyll from `<Page>.md`
  - `xcore/netex/elements/<Element>.html` and `site/netex-html/<Element>.html` are generated by the xcore tool from the NeTEx XSD; the element name is checked against the XSD (links are skipped with an info message if the XSD is not available)
- Allows links that leave the docs folder but stay inside the project folder (e.g. `../../tools/...` from `src/templates/README.md`)
- Provides detailed warnings for broken links
